# Round B10 — Add a selectable virtual environment background

Owner voice. Run this in CLAD, then report back with evidence.

## Context

The Lens currently uses the real camera passthrough as its background (DeviceTracking
World). For the demo I want the option of a **virtual environment** background — a
selectable scene (e.g. a city street, a billboard, a studio) behind the signing hand
and HUD. This should use Lens Studio's plug-and-play environment features, not a
hand-built scene from scratch.

I believe Lens Studio ships built-in environments (skyboxes, environment prefabs)
and the Asset Library has environment assets. Use those. Do not build a full 3D
environment by hand unless no plug-and-play option exists.

## What I want

1. **Add at least one selectable virtual environment background.** Investigate and use
   Lens Studio's plug-and-play environment path (built-in environment / skybox,
   Asset Library environment prefab, or an Environment / skybox component). Prefer
   whatever requires no hand-built geometry.
2. **Make it selectable.** Add a way to switch between the real passthrough background
   (default) and the virtual environment — e.g. a HUD toggle/button (UI Kit, same
   pattern as mic/share) or an inspector option. The user should be able to flip it
   during the demo.
3. **Keep the hand, HUD, and interactions working** with the virtual background — the
   wire/bead hand and HUD must render on top correctly.
4. **Keep the verified core untouched** otherwise (resolver, SIK prefab, typed-input
   loop). Only add the environment + its selector.

## Success criteria (report each)

- A virtual environment renders as the background in Desktop Preview (report the
  asset/path used — built-in or Asset Library, not hand-built).
- The user can switch between real passthrough and the virtual environment (describe
  the control).
- The wire/bead hand + HUD render correctly on the virtual background.
- The typed-input loop still works.
- Zero TypeScript errors; no new runtime exceptions (list any warnings).

## Report back

- The environment asset you used and its source (built-in / Asset Library / custom),
  and why you chose it over building from scratch.
- Literal file paths changed and the actual diffs.
- How the switch control works (button/inspector) and its placement.
- A screenshot or capture path of the Preview showing the hand + HUD on the virtual
  background.
- Compile/verify command run and its output.
