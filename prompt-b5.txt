# Round B5 — HUD + text input fix

Owner voice. Run this in CLAD, then report back with evidence.

## Context

The HUD panel and text input do not work in the Preview. Clicking "Type to sign…"
does not focus the field or accept input, and the HUD readouts are not displayed
properly. The build stages before this were verified, but this round's wiring is
incomplete.

I have diagnosed the cause myself:

1. The scene has NO `SpectaclesInteractionKit` prefab at root. The UIKit
   `TextInputField` and `Button` components extend `Element`, which at
   initialization creates an `Interactable` and `InteractableStateMachine` on the
   element. Those only receive hand/controller input when the SIK interaction
   layer (InteractionManager + HandInteractors) exists in the scene. Without it,
   the text field cannot be focused or typed into, and the button cannot be
   triggered.
2. `Assets/Scripts/SignSpaceHUD.ts` builds the HUD at runtime, but it was written
   against a UIKit API I now know is wrong:
   - It calls `mic.setVariant(...)` AFTER `createComponent(Button.getTypeName())`.
     The Button API requires `setVariant`/`setTheme` to be called BEFORE the
     component initializes; calling it after initialization is a no-op or falls
     back to the theme default.
   - The HUD panel and readouts are created in a world-space scene object that has
     no screen-space UI canvas, so positioning and rendering are not the layout I
     intended.

## What I want

Fix the HUD so it displays correctly and the text input actually accepts input in
the Desktop Preview, using the correct SIK + UIKit patterns.

1. **Add the SIK interaction layer.** Instantiate the
   `SpectaclesInteractionKit` prefab at scene root (path
   `SpectaclesInteractionKit.lspkg/Prefabs/SpectaclesInteractionKit.prefab`),
   root placement required. Do not hand-build an interaction layer from scratch.
2. **Fix the runtime HUD build** in `Assets/Scripts/SignSpaceHUD.ts`:
   - Use the correct UIKit setup for world-space UI, or parent the HUD under a
     proper UI Canvas so readouts render in the intended layout. Pick whichever
     the current Lens Studio + UIKit version supports and document the choice.
   - Call `setVariant` (or `setTheme`) on the mic button BEFORE its
     initialization path, or set the fields directly in a way the component
     honors.
   - Keep the heard / sign cue / gloss readouts, the text input, and the mic
     button.
3. **Keep the existing verified behavior:** the hand still renders warm cream and
   plays `HELLO` on start, whole-word signs plus fingerspell fallback still work,
   and the ASR path still degrades gracefully.

## Success criteria (report each)
